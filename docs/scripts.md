# Scripts

Detailed reference for the scripts in `src/`. The [README](../README.md) has the short table and the commands of the full pipeline.

## 1. Data Engineering
*   **`download_vww_subset.py`**: Downloads a balanced `person` / `non_person` subset of MS-COCO 2017, labelled with the Visual Wake Words rule (a person covering at least 0.5% of the image; images with only smaller or crowd persons are left out). `--coco_split` picks `val2017` (default) or `train2017`, `--per_class` the number of images of each class, `--seed` the selection, and `--output_dir` the folder that receives `person/` and `non_person/`. Only the annotation file of that split and the selected JPEGs are fetched. The selection is deterministic: the script prints, and writes to `vww_subset_report.json`, a `selection_sha256` over the chosen file names, so two downloads can be checked to be the same subset. A re-run downloads only the files that are missing.
*   **`process_images.py`**: Converts raw dataset images (JPEG, PNG, BMP) to single-channel grayscale, applying optimized compression parameters (JPEG Quality: 70, PNG Compression: 9) to prevent bloating storage.
*   **`reshape_images.py`**: Recursively searches for images and resizes them to the target resolution required by models (e.g. `160x120`, `320x320`), storing the structured dataset in `data/processed/{width}x{height}`. With `--balance undersample` it also balances the classes, randomly discarding images from the larger classes down to the size of the smallest (`--max_per_class N` adds a hard cap, `--seed` — default 42 — fixes which images are kept, and `--dry_run` prints the per-class counts without writing anything). Balancing lives here, before partitioning, because `split_dataset.py` is stratified on purpose: it preserves the class ratio, it does not correct it. Only undersampling is offered: duplicating images before the split would put identical copies in `train` and `test` and inflate every level's accuracy. Each run writes `reshape_report.json` (counts, discards, seed) next to the images, and with the default `--balance none` it warns when the classes are imbalanced.
*   **`split_dataset.py`**: Partitions the reshaped dataset into disjoint `train`/`val`/`test` splits (default 70/15/15, `--seed 42`), stratified per class. Writes the images plus `{train,val,test}_manifest.csv` and `split_report.json` (counts, class balance, integrity checks). `test_manifest.csv` carries a `hil_subset` column that marks a fixed, class-balanced subset of the test split (default 200 images, `--hil_subset`) for the physical HIL rig, which is far slower per image than the PC levels. The classes are the subfolders of `--input_dir`, labelled in alphabetical order (the order training assigns); `--class_names_path` imposes the order of an explicit file instead, whose classes must be exactly those subfolders. With `--test_input_dir` the test images come from a second folder with the same class subfolders: all of it becomes the test partition and `--input_dir` only feeds `train` and `val` (pass `--test 0`), which is how the COCO partition keeps training and test images in different COCO splits. When the output folder already holds manifests, the script says whether the new partition is the same and leaves identical files untouched, so rebuilding a published partition changes no versioned file.

**Common Output Artifacts for Data Engineering:**
- **Grayscale Images**: `data/processed/grayscale/{class_name}/*.jpg` - The compressed, single-channel intermediate dataset.
- **Reshaped Datasets**: `data/processed/{width}x{height}/{class_name}/*.jpg` - The final model-ready dataset structured by resolution and class.
- **Reshape Report**: `data/processed/{width}x{height}/reshape_report.json` - Per-class counts before and after balancing, and the seed. Lives with the images under `data/processed/`, which is git-ignored.
- **Partition**: `data/splits/{train,val,test}/` plus `data/splits/*_manifest.csv` and `split_report.json`. `data/splits/` is the working folder of your own partition and is git-ignored as a whole. The partitions behind the published results live in named folders, `data/splits_coco/`, `data/splits_plates/` and `data/splits_vww/`: their manifests and reports are versioned, so the exact partition can be rebuilt, and their images are git-ignored. `data/splits_coco/` also keeps the reports of its two downloads (`subset_report_train2017.json`, `subset_report_val2017.json`).

## 2. Model Training (ML Pipelines)
*   **`train_mobilenet.py`**: Training pipeline for MobileNet classification architectures (`MobileNet`, `MobileNetV2`, `MobileNetV3Large`, `MobileNetV3Small`) utilizing Transfer Learning from ImageNet weights, adapted to single-channel (grayscale) inputs and custom number of classes. Supports data augmentation and generates `.keras` models. By default the ImageNet backbone is frozen and only the new classifier is trained; `--trainable_backbone` trains every layer from the ImageNet weights, and `--weights none` from random weights.
*   **`train_resnet.py`**: Training pipeline for ResNet classification architectures (`ResNet8`, `ResNet18`) adapted for tiny edge classification, trained from random weights.
*   **`train_squeezenet.py`**: Training pipeline for the `SqueezeNet` architecture, trained from random weights. `--kernel_initializer he_normal` and `--batch_norm` are for a dataset on which the published network does not start to learn (see the training recipe below).

**Common Input for Training Scripts:** the `train` and `val` partitions produced by `split_dataset.py` (`--splits_dir`, default `data/splits`). The scripts no longer accept `--validation_split` — the partition is fixed on disk instead of resampled in memory, so the hyper-parameter no longer appears in the artifact names either (`{model}[_{tag}]+{batch}+{epochs}+{lr}+{W}+{H}`). If the partition is missing, training stops and prints the `split_dataset.py` command to run. Both partitions are read once through `images.py` (`.png` and `.jpg` files alike) and kept in memory as raw `uint8` pixels, 1.9 GB for 100,000 images of 160×120, so training sees the bytes the evaluation levels see and the images are shuffled one by one at every epoch.

**Run names and overwrite protection:** `--tag NAME` adds a run name after the architecture (`MobileNetV2_VWW+32+20+0.0001+160+120`), and the `.tflite` and every result file of that model inherit it; use one tag per dataset. Tags take letters, digits, `_` and `-`. Training, quantization and the MIL and SIL evaluations stop before replacing an existing output and say which files are in the way; `--overwrite` allows it. Without a tag a run takes the names of the published models, whose training curves and results are versioned, so it stops unless `--overwrite` is given.

**Training recipe:** Without options the three scripts train as they did for the published models: a constant learning rate with early stopping on the validation loss (patience 5; `train_resnet.py` and `train_squeezenet.py` also halve the rate when that loss stops improving), the augmentation of each script (horizontal flip, zoom of 10% and a rotation of up to 0.2 of a turn for the MobileNets, 0.15 for the other two) and, for the MobileNets, a frozen ImageNet backbone under a new classifier. The options below add what the reference trainings of person detection on COCO have in common; the MLPerf Tiny reference model for Visual Wake Words, for one, trains every layer for 50 epochs with a stepped rate and a mild augmentation.

- `--lr_schedule stepped` runs every epoch asked for and halves the rate at 40% and at 60% of them (for 50 epochs: 20 at `--learning_rate`, 10 at half and 20 at a quarter, the schedule of MLPerf Tiny). Nothing stops the run early; the checkpoint is still the epoch with the best validation accuracy.
- `--augmentation light` uses a horizontal flip, a rotation of up to 10°, shifts of up to 5% and a zoom of up to 10% (MLPerf Tiny). It is applied to each batch before it reaches the model, as one affine transform per image, so the saved model holds no augmentation layers. The standard augmentation is made of layers inside the model, which costs time on the GPU when every layer is trained: an epoch of `MobileNetV2` over 10,200 images took 29.5 s with it and 5.1 s with the light one.
- `--trainable_backbone` (`train_mobilenet.py`) trains every layer, starting from the ImageNet weights; the batch-normalisation layers then follow the new data. `--weights none` starts from random weights instead.
- `--kernel_initializer he_normal` and `--batch_norm` (`train_squeezenet.py`) are for a network that stays at a constant output; see the pilot below.

The run name does not carry the recipe, only the batch size, the epochs and the starting learning rate, so two recipes with those three in common need different `--tag`s (the overwrite guard stops the second one otherwise). The recipe of a model is in its training record.

**What the options gave in a pilot:** Measured on the GPU (WSL2, RTX 2080 SUPER, TensorFlow 2.21.0) with 10,200 training and 1,800 validation images of COCO `train2017` (160×120 grayscale, two balanced classes), batch 32, seed 42, 10 epochs. Best validation accuracy:

| Architecture | Default recipe, 1e-4 | Options, 1e-3 | Options, 3e-4 | Options, 1e-4 |
|---|---|---|---|---|
| `MobileNet` | — | 0.801 | 0.814 | 0.808 |
| `MobileNetV2` | 0.778 | 0.800 | 0.792 | 0.797 |
| `MobileNetV3Small` | — | 0.787 | 0.814 | 0.809 |
| `MobileNetV3Large` | — | 0.839 | 0.854 | 0.846 |
| `ResNet8` | 0.637 | 0.674 | 0.689 | — |
| `ResNet18` | — | 0.629 | 0.662 | — |
| `SqueezeNet` | 0.500 | 0.500 | 0.500 | 0.500 |
| `SqueezeNet`, `--kernel_initializer he_normal` | — | 0.500 | 0.620 | 0.662 |
| `SqueezeNet`, `--batch_norm` | — | 0.689 | 0.707 | — |

"Options" is `--lr_schedule stepped --augmentation light`, plus `--trainable_backbone` for the MobileNets; a dash is a combination that was not run. Ten epochs on a tenth of the data show whether a configuration learns and at which rate, not the accuracy of a full training, and with 1,800 validation images differences under 0.02 are not resolved. Three things do stand out:

- From random weights (`--weights none`, 1e-3) the MobileNets did not learn in ten epochs on this amount of data (0.583 for `MobileNet`, 0.500 for `MobileNetV2` and `MobileNetV3Small`), which is why the options keep the ImageNet weights as the starting point.
- `ResNet8` and `ResNet18` learn slowly from random weights and were still improving after ten epochs: over 30 epochs at 3e-4 they reached 0.748 and 0.741 (`ResNet8` at 1e-3: 0.732).
- `SqueezeNet` as published stayed at a constant output at the three rates, and with the default recipe. With `he_normal` it learned at 1e-4 with five seeds out of five (0.595 to 0.662 in ten epochs, 0.679 in 30), at 3e-4 with one seed out of two and at 1e-3 not at all. With `--batch_norm` it learned at 1e-3 and at 3e-4 (0.688 and 0.707 with two seeds at 3e-4, 0.728 in 30 epochs). `he_normal` only changes the starting weights. `--batch_norm` adds a layer after every convolution of the backbone, so it is not the network of the published models, although the converter folds those layers into the convolutions and the INT8 file has the same operators. Removing the ReLU after the last convolution, without either option, did not help (0.500 at 1e-3 and at 1e-4).

Freezing the batch-normalisation statistics of the backbone while every layer is trained was also tried at 3e-4: +0.023 for `MobileNetV2`, −0.014 for `MobileNetV3Large` and under 0.005 for the other two, so the scripts let them follow the data.

**Seed:** `--seed` (default 42) is set once for Python, NumPy and TensorFlow before the data pipeline and the model are built, so it fixes the initial weights, the shuffling and the augmentation. What that gives was measured. On a CPU (Windows 11, TensorFlow 2.21.0, Keras 3.15.1; 300 images, 3 epochs) two runs with the same seed gave the same per-epoch history and bit-identical weights for `ResNet8`, `MobileNetV2` and `SqueezeNet`. On the GPU used for training (WSL2, RTX 2080 SUPER, TensorFlow 2.21.0, Keras 3.13.2; the COCO partition, 3 epochs) they did not. For `MobileNetV2`, whose backbone is frozen, the two histories agree to 2e-7 and the validation accuracy is the same to four decimals, but the weights are not bit-identical. For `ResNet8`, trained from scratch, the runs drift apart from the first epoch (validation accuracy 0.5928 and 0.5872 after three epochs), because some GPU kernels are not deterministic; TensorFlow's op-determinism mode is not enabled by the scripts. So a seed repeats a CPU run exactly and makes GPU runs start alike, no more: compare the history in the training record instead of assuming two runs are equal. The models published so far were trained before the seed existed and are distributed as files.

**Common Output Artifacts for Training Scripts:**
- **Keras Model**: `models/checkpoints/{model_name}+{hyperparameters}.keras` - The trained FP32 model ready for evaluation or quantization.
- **Class Names**: `models/checkpoints/{model_name}+{hyperparameters}.classes.txt` - Label order of the run, one class per line, written next to its checkpoint; quantization copies it next to the `.tflite`, and the evaluators read it from there. `models/class_names.txt` is the label order of the published plates models, which predate the per-model file, and is used when a model has none.
- **Training History Plot**: `results/training_curves/{model_name}_training_history+{hyperparameters}.png` - Matplotlib visualization of training/validation loss and accuracy.
- **Training Record**: `models/checkpoints/{model_name}+{hyperparameters}.training.json` - What produced the checkpoint: seed, settings, partition, per-epoch history and software versions (Python, TensorFlow, Keras, NumPy, Pillow, platform, GPUs). The settings hold the whole recipe: the learning rate of each stage, whether early stopping applied, the augmentation and its parameters and, per script, the starting weights and what was trained (MobileNets) or the initialiser and batch normalisation (SqueezeNet). `data` holds the number of images of each class the loader read.

## 3. Model Optimization & Evaluation
*   **`mil_benchmark.py`**: The **MIL** level. Evaluates Keras `.keras` models by generating core statistics (Accuracy, Precision, Recall, F1-Score) and exporting a detailed classification report alongside a saved Seaborn-based Confusion Matrix plot. Requires an explicit `--model_path`, reads through `images.py` the held-out `<splits_dir>/test` partition (`--splits_dir`, default `data/splits`, or an explicit `--data_dir`), never the full dataset, so the reported accuracy excludes the images the model trained on, and writes its Confusion Matrix to `results/mil/` alongside the other levels' outputs. Next to the plot it writes `metrics_{model}.json` — global metrics including weighted *and* macro F1, the per-class report, the raw confusion matrix, and the SHA-256 and size of the evaluated `.keras` — and `predictions_{model}.csv`, one row per test image.
*   **`prune_model.py`**: Optional step. Applies manual magnitude-based unstructured pruning (either globally or layer-wise) to sparsify weights in Conv2D and Dense layers. Calculates and outputs initial/final model sparsity. It keeps tensor shapes, so it does not reduce the `.tflite` size, and no published result uses it.
*   **`quantize_int8_basic.py`**: Quantizes standard FP32 `.keras` models to full-INT8 `.tflite` format. Calibrates activation scales and zero-points with a representative dataset drawn **exclusively from `<splits_dir>/train`** (`--calib_samples`, default 100; `--calib_seed`, default 42, which fixes exactly which `.tflite` is produced): the sorted file list is shuffled with the seed and its first images are read with `images.py`, so the choice does not depend on the operating system or on the TensorFlow version, and calibration sees the pixels the evaluation levels see. Quantization is post-training; much of the literature on this task uses quantization-aware training instead, which PHLAME does not implement. Calibrating on `test` would fit the activation ranges to the evaluation distribution and inflate the SIL/PIL/HIL accuracy; `val` is left out too, since early stopping already consumed it to select the model. Enforces strict INT8 input/output tensors for optimal MCU compatibility.
*   **`sil_benchmark.py`**: The **SIL** level. Validates full-INT8 `.tflite` quantized models sequentially. Simulates microcontroller execution constraints by performing manual input scaling/quantization and output dequantization dynamically, exporting a Seaborn-based Confusion Matrix. Reads `<splits_dir>/test` (`--splits_dir`, default `data/splits`) through `images.py` — the same partition MIL, PIL and HIL consume, with the same bytes per image as MIL and the PIL bench, and disjoint from the `train` split used to calibrate the quantization, so the MIL→SIL gap is attributable to quantization alone and not to a different sample of images. Writes its Confusion Matrix, `metrics_{model}.json` (same schema as MIL, hashing the `.tflite`) and `predictions_{model}.csv` to `results/sil/`, named after the model like the other levels. `--kernels` chooses the TFLite kernels that run the model on the PC and is recorded as `model.kernels`: `default` (what the interpreter picks, which includes the XNNPACK delegate), `builtin` (the built-in optimized kernels without that delegate) or `reference` (the reference kernels, the ones TFLite-Micro is derived from). The three do not give the same prediction for every image, and the default interpreter refuses some valid INT8 files (a tensor that is constant over the calibration images gets a degenerate scale); the run then stops and names the other two.

**Common Output Artifacts for Optimization & Evaluation:**
- **Confusion Matrix (MIL)**: `results/mil/confusion_matrix_{model_name}.png` - Visual evaluation of the floating-point model's predictions on the held-out test partition.
- **Pruned Model**: `models/checkpoints/{model_name}_pruned.keras` - The sparse representation of the model after magnitude pruning.
- **Quantized TFLite Model**: `models/tflite/{model_name}_int8.tflite` - The fully integer quantized, microcontroller-ready binary file.
- **Confusion Matrix (SIL)**: `results/sil/confusion_matrix_{model_name}_int8.png` - Visual evaluation of the quantized model simulating MCU arithmetic constraints.
- **Metrics (MIL / SIL)**: `results/{mil,sil}/metrics_{model_name}[_int8].json` - Machine-readable metrics plus the model's SHA-256 (see [Results Format](../README.md#results-format)).
- **Per-Image Predictions (MIL / SIL)**: `results/{mil,sil}/predictions_{model_name}[_int8].csv` - True and predicted class for every test image.

## 4. Embedded Conversion & Deployment
*   **`tflite_to_c.py`**: Standardized converter utility that parses a `.tflite` binary file and outputs a C/C++ array header compatible with TFLite for Microcontrollers. Embeds a critical 16-byte alignment attribute (`DATA_ALIGN_ATTRIBUTE`) required for hardware accelerators and optimal execution on ARM Cortex-M7 (e.g., Arduino Portenta H7). Writes `model.h` into both firmware sketches by default (`--target pil|hil|both`), keeping the PIL and HIL benches on the same model; an explicit output path can still be passed as a second argument.
*   **`compile_upload_arduino.py`**: Automation utility that interacts directly with `arduino-cli` to compile and upload the firmware. `--target pil|hil` selects which of the two sketches to flash (the board runs one at a time) and `--board portenta|nicla` the board to build for (default `portenta`). It installs the board's core if it is missing (`arduino:mbed_portenta` or `arduino:mbed_nicla`), auto-detects the connected board's COM port, and prints the flash and RAM use reported by the compiler. `--compile_only` stops after compiling, so no board is needed. `--arena_kb` and `--image_buffer_bytes` set the size of the tensor arena and of the image buffer compiled into the sketch; they matter on the Nicla Vision, where both live in internal RAM (see [Hardware and Porting](hardware.md#boards-and-memory)).
*   **`pil_benchmark.py`**: The **PIL** level. It sends dataset images to the board via a custom Serial protocol (with byte escaping). It reads predictions back in real-time, matching them with the true folder-based classes to generate extensive statistical metrics and a Seaborn-based Confusion Matrix plot comparing on-chip inference with ground-truth. Streams `<splits_dir>/test` by default (`--splits_dir`, default `data/splits`) — the same held-out partition MIL and SIL evaluate, so the SIL→PIL gap isolates the move to real silicon. Names its Confusion Matrix and latency CSV after the `--model_path` flashed on the board, matching `mil_benchmark.py`, so successive runs on different models accumulate instead of overwriting. Data is injected over the wire — the camera is not in the loop. It also writes `metrics_{model}.json` — the MIL/SIL schema plus the run configuration and a per-field latency summary (n, mean, median, std, min, max, p95) — and `predictions_{model}.csv`. The JSON is written even when there are no labels or scikit-learn is missing, because latency is what this level uniquely contributes. If the serial link drops during a run, the bench reopens the port and sends the same image again (see [Hardware and Porting](hardware.md#serial-protocol-pil-bench)).
    - **The board is checked before anything is measured or written.** The bench reads the identity lines of the firmware (from its boot lines, or by asking with an empty packet `#@` when the firmware was already running) and stops with exit code 2 unless: the board is the one given with `--board`; the FNV-1a fingerprint and the size of the model in flash are those of the `.tflite` given with `--model_path`, which the bench hashes but never executes; and the images have the input shape the firmware announces. `--width` and `--height` are optional and default to that shape; until November 2026 they defaulted to 320×320, and a run without them sent images of the wrong size and finished as if nothing were wrong. A run refused here leaves the files of an earlier run untouched.
    - **`--allow_model_mismatch`** (debugging only) measures although the model could not be verified: another fingerprint, a `--model_path` that is not a file, or a firmware built before November 2026, which prints no fingerprint and no input shape (so `--width` and `--height` must be given). The run is recorded with `model.identity_verified = false`.
    - **`--max_unanswered N`** (default 5; 0 never gives up): after N images in a row without an answer, each of which waits 30 s, the run ends. On 3 November 2026 a board that had stopped kept a run waiting for 1.5 hours.
    - **A run that is cut short keeps what it measured.** The two CSV files are written row by row. If the serial link is lost for good, the board stops answering, the operator presses Ctrl+C or an image cannot be read, `metrics_{model}.json` is still written, with `run.completed = false`, the reason in `run.stopped_because`, the number of images planned in `dataset.n_images_planned` and figures that cover only the images recorded, and the bench ends with exit code 3.
    - *Exit codes:* 0 complete run; 1 the run could not start (port, images, a board that does not answer, output files that would be replaced); 2 refused before measuring (wrong board, model not verified, input shape); 3 run cut short.

**Common Output Artifacts for Embedded Conversion & Deployment:**
- **C Model Header**: `deployment/{pil_firmware,hil_firmware}/model.h` - 16-byte aligned C byte array (`g_model[]` and `g_model_len`) linked into the PIL and HIL firmware sketches.
- **Confusion Matrix (PIL)**: `results/pil/confusion_matrix_{model_name}_int8.png` - Visual evaluation of on-chip inference against the held-out test partition.
- **Per-Phase Latencies (PIL)**: `results/pil/latency_metrics_{model_name}_int8.csv` - Per-image cycle counts (`CYC_*`), microsecond latencies (`US_*`), and MCU temperature.
- **Metrics (PIL)**: `results/pil/metrics_{model_name}_int8.json` - Machine-readable classification metrics, run metadata, and per-phase latency statistics (see [Results Format](../README.md#results-format)).
- **Per-Image Predictions (PIL)**: `results/pil/predictions_{model_name}_int8.csv` - True and on-chip predicted class for every test image.

## 5. Camera-in-the-Loop HIL Evaluation
*   **`hil_benchmark.py`**: The **Hardware-in-the-Loop (HIL)** bench. The host displays each dataset image on-screen as a controlled visual stimulus; the board's own camera (the **HM01B0** of the Portenta Vision Shield, or the **GC2145** built into the Nicla Vision) captures the physical scene and runs the full sensor→prediction pipeline on-device, so ground truth is known by construction (the label of the displayed stimulus). Stimuli come from `data/splits/test_manifest.csv`: by default the images flagged `hil_subset == 1` (200, balanced across classes), `--all_test` for the whole test split, or `--folder` to bypass the manifest. Before measuring, the bench compares the FNV-1a fingerprint that the firmware prints at boot with that of the expected `.tflite` (`--tflite`, or `--sil_model` if omitted) and aborts on a mismatch, when no `.tflite` is given (`--model_tag` only names the output files) or when the firmware reports no fingerprint; it also aborts if `--lux`, `--distance_cm` or `--ambient_temp` are missing (`--allow_model_mismatch` and `--allow_missing_conditions` exist for debugging and smoke tests, and mark the run accordingly), and warns (`warn_condition_drift()`) if any physical condition differs from previous sessions in the board's results folder. Records per-phase latency (`CAPTURE`/`PRE`/`INF`/`POST`/`TOTAL`, via DWT cycle counter) and rig conditions alongside predictions. Optionally recovers the exact captured frame (`--dump_frames`) to cross-run it through the **MIL** (`--mil_model`) and **SIL** (`--sil_model`) levels on the PC, decomposing the end-to-end gap into its quantization (MIL vs SIL), execution (SIL vs HIL), and physical-frontend (PIL vs HIL) components. The stimulus window opens full-screen where the system puts it: `--monitor N` sends it to a given monitor (Windows only; recorded as `stimulus_monitor`) and `--windowed` keeps it as a normal window. The bench waits for ENTER before the first stimulus unless `--no_confirm` is given, which is needed where there is no interactive terminal. Each stimulus stays on screen for `--settle` seconds before its capture, and a key pressed in the stimulus window does not shorten that time.
    - **A session that is cut short keeps what it measured.** Every row is appended to `latency_metrics_{model}.csv` as soon as its stimulus is measured, and the other files are written however the sweep ends: a lost serial link, a board that stops answering (the sweep ends after 5 stimuli in a row without a response, instead of waiting 30 s for each of the rest), Ctrl+C, an error, or a stimulus image that cannot be displayed. Such a run is marked `completed: false` in the conditions and metrics files, with the number of stimuli planned (`n_stimuli_planned`) and the reason (`stopped_because`); its metrics cover only the stimuli measured, and the script ends with exit code 3. `build_ladder_tables.py` does not take it for a full session: it stops when the CSV does not hold exactly the rig images.
    - **Active thermal control (constant-speed fan):** The stimulus rig uses active forced-air cooling over the Portenta H7 + Vision Shield to keep the MCU temperature stable during a session. Across the four protocol sessions (`rep1`–`rep4`, 200 inferences each), the first-to-last temperature difference is −1 to +2 °C (the internal sensor has a 1 °C step), the within-run temperature standard deviation is 0.59–0.62 °C, and the temperature–total-latency correlation is |r| ≤ 0.09 (p ≥ 0.20), which shows no sign of thermal throttling.
    - **`--sil_kernels`** chooses the TFLite kernels that run `--sil_model` on the PC (`default`, `builtin` or `reference`, as `sil_benchmark.py --kernels`) and is recorded in the conditions and metrics files. Use the kernels of the SIL run the captured-frame SIL is compared with: the default interpreter does not give the chip's prediction for every image and refuses some valid INT8 files.
    - Firmware companion: `deployment/hil_firmware/hil_firmware.ino` — a dedicated sketch, independent from the PIL firmware (`pil_firmware.ino`), which remains untouched as a serial-only fallback.
    - Repeated runs of the same model go to their own folder, e.g. `results/hil/rep1/` with `--model_tag MobileNetV2_rep1`, so a session never overwrites another.
*   **`calibrate_hil_rig.py`**: Checks the rig before an HIL session, through the stimulus window and the serial protocol of the bench, so what it measures is what the bench will see. The board runs the HIL firmware; the model inside it does not matter. `--live` repeats a geometry pattern (four corner squares and a centre one) and says how to move the camera — closer or away, left or right, roll — until Ctrl+C. `--report` shows each pattern once and writes `calibration_{UTC time}.json`, with a picture of every pattern next to its captured frame, to `results/hil/calibration/` (`results/nicla/hil/calibration/` with `--board nicla`): shift, scale, rotation and residual of the geometry fit; the captured level of eight gray bands, their range and the clipped fraction; the corner-to-centre ratio of a flat field and the spread of its mean over `--repeats` captures; the contrast of a fine checkerboard against a coarse one; and, for the test images given with `--images`, the correlation between the image shown and the frame captured. Each figure is compared with an acceptance criterion written in the report and shown as PASS or WARN; nothing is enforced. Use the same `--settle`, `--windowed` and `--monitor` as in the session that follows. Its figures on real frames are still to be checked: see [HIL Rig and Session](hardware.md#hil-rig-and-session).

**Common Output Artifacts for Camera-in-the-Loop HIL Evaluation:**
- **Confusion Matrix (HIL)**: `results/hil/confusion_matrix_{model_name}_int8.png` - Visual evaluation of the camera-in-the-loop inference compared with the displayed stimulus ground truth.
- **Metrics (HIL)**: `results/hil/metrics_{model_name}_int8.json` - Classification metrics (same schema as MIL/SIL/PIL), on-chip vs. file `FNV-1a` fingerprint verification, cross-validation summary, and per-phase latency statistics (see [Results Format](../README.md#results-format)).
- **Per-Phase Latencies & Cross-Run Predictions (HIL)**: `results/hil/latency_metrics_{model_name}_int8.csv` - One row per inference with `CAPTURE`/`PRE`/`INF`/`POST`/`TOTAL` latency (`CYC_*` and `US_*`), MCU temperature, stimulus ground truth, and paired HIL/SIL/MIL predictions on the same captured frame.
- **Rig Conditions (HIL)**: `results/hil/conditions_{model_name}_int8.json` - Environmental protocol of the stimulus rig (illuminance in lux, camera-to-screen distance in cm, ambient temperature in °C, notes) and model identity.
- **Captured Camera Frames (optional, `--dump_frames`)**: `data/hil_frames/frame_{idx}_{class}_{image}.png` - Exact 160×120 grayscale frames captured by the HM01B0 sensor and streamed back over serial for cross-level MIL/SIL evaluation.

## 6. Statistical Analysis
*   **`build_ladder_tables.py`**: Rebuilds the eight fidelity-ladder tables reported in the paper from the per-image result files (`results/{mil,sil,pil}/predictions_*.csv`, `results/hil/latency_metrics_*.csv`, `results/hil/rep*/`): paired bootstrap 95% CIs (10,000 resamples, seed 20261016), exact McNemar tests with Holm correction, per-class Fisher tests, per-phase latency, HIL repeatability and the PIL attribution check. Deterministic: every run produces identical numbers.
    - *Usage:* `python src/build_ladder_tables.py` (overwrites the versioned `results/tables/`; pass `--output_dir` to write elsewhere)
    - *Outputs:* `results/tables/ladder_tables.md`, `ladder_tables.tex`, `table*.csv` (unrounded values), `ladder_summary.json` (headline numbers, SHA-256 of every input file, library versions).
    - **Another benchmark.** Without options the script builds the tables of the vehicle benchmark. A benchmark that has the four levels is named by its runs and its partition: `--tag` (the tag given to the training scripts; the runs are `{architecture}_{tag}{run_suffix}`), `--run_suffix` (the rest of the run name, `+batch+epochs+lr+W+H`; `--tag_suffix` is its earlier name and still works), `--splits_dir` (the partition: its `test_manifest.csv` gives the rig subset and the class names; `--class_names` and `--manifest` override them), `--archs` and `--deployable`, and `--board` (PIL and HIL are read from `results/{pil,hil}`, or from `results/nicla/{pil,hil}` with `--board nicla`). The tables then go to `results/tables/<tag in lower case>/`, so two benchmarks do not replace each other's, and `ladder_summary.json` records those options. Only `results/mil`, `results/sil` and the board folders are read: the alternative SIL runs of `results/sil_kernels/` are never taken for a level. HIL repeatability runs are looked for in `<hil folder>/rep*/` as `{architecture}[_{tag}]_{rep folder}`; a rep folder without a run of the benchmark is left out. When a level has not been measured the script stops and lists what is missing, by level and architecture (for a benchmark measured up to PIL, use `build_benchmark_table.py`); it also stops when the partition or the class names are not those of the result files, or when a run filed under one board was measured on the other.
    - *Example:* the four-level Visual Wake Words run of the repository, `python src/build_ladder_tables.py --tag VWW --archs MobileNetV2 --deployable MobileNetV2 --splits_dir data/splits_vww`, and the COCO benchmark once its HIL runs exist, `python src/build_ladder_tables.py --tag COCO --run_suffix +32+50+0.0003+160+120 --splits_dir data/splits_coco`.
*   **`build_benchmark_table.py`**: Rebuilds the summary table of a benchmark measured up to PIL from the result files, for the runs of one tag (`--tag COCO` gathers the runs named `{architecture}_COCO+...`). For each run it reads MIL (`results/mil/`), the SIL of record (`results/sil/`), the PIL run of each board (`results/pil/`, `results/nicla/pil/`) and, when present, the same SIL run with other TFLite kernels (`results/sil_kernels/<kind>/`), and counts image by image, joined on `RelPath`, how many predictions two levels share: MIL = SIL, SIL = PIL on each board, one board against the other, and each alternative SIL against the SIL of record and against the board. Standard library only; it needs no model, image or board.
    - *Usage:* `python src/build_benchmark_table.py --tag COCO` (`--boards portenta,nicla` chooses the boards and their column order; `--output_dir` writes elsewhere)
    - *Outputs:* `results/tables/benchmark_<tag>.csv` (one row per run, unrounded) and `benchmark_<tag>.md` (the table of levels and the table of SIL kernels).
*   **`compare_results.py`**: Says whether a reproduced run gives the published result. It compares every `metrics_*.json` under a folder with the file of the same level and name under `results/`: the evaluated model file (SHA-256 and size), the class names, the number of images, the global and per-class metrics, the confusion matrix and, image by image, the predictions of `predictions_*.csv`. The timestamp, the recorded paths and their separators, and the latency measured on a board are left out. Exit code 0 only when every compared run is identical. Standard library only.
    - *Usage:* `python src/compare_results.py results/smoke_test results` after running a level with `--output_dir results/smoke_test/{mil,sil,pil}`.

*   **`find_near_duplicates.py`**: Checks whether the test split of a partition is independent of its training data. It compares every test image with the train and validation images and reports exact duplicates and near-duplicates (the same photo re-encoded, resized, rotated or mirrored), with thresholds calibrated on the partition itself. Writes `near_duplicates.csv`, `near_duplicates_within_test.csv`, `near_duplicates_review.csv` and `near_duplicates_summary.json`. A run over 13,000 images takes 20 to 25 minutes. Method and limits: [`data_independence.md`](data_independence.md).
    - *Usage:* `python src/find_near_duplicates.py --splits_dir data/splits --output_dir results/smoke_test/independence` (`--region center` when the subject fills the centre of the frame).
*   **`independence_report.py`**: Recomputes accuracy and macro-F1 of every published run of a partition without the test images listed by the detector, with a paired bootstrap interval of the difference, and writes `results/tables/independence_{partition}.csv`.
    - *Usage:* `python src/independence_report.py --splits_dir data/splits_coco` (`--overwrite` to replace the published table).

## 7. Model Files
*   **`verify_models.py`**: The model files (`.keras`, `.tflite`) are not in git; `models/checksums.sha256` lists the SHA-256 of every one a published result refers to. Without options the script checks the files present in `models/` against that list (`--require_all` fails if one is missing). `--results` checks instead that the digest recorded in every `metrics_*.json` and `conditions_*.json` is in the list. `--download <tag>` fetches the archives attached to a release, unpacks them and checks them; `--bundle <dir> --tag <tag>` is the maintainer's side and writes those archives, and `--update_list --set <set>` rewrites the entries of one set of the list from the model files that its published results name. "Published" means tracked by git: the results of a user's own runs, which the usage steps write next to the published ones, are not checked against the list.
*   **`count_macs.py`**: Counts the multiply-accumulate operations (MACs) of `.tflite` models, per operator type and in total, and writes one row per model to a CSV with the SHA-256 of the file (`python src/count_macs.py "models/tflite/*_COCO+*_int8.tflite" --output results/tables/macs_COCO.csv`). Counted: `CONV_2D` (output elements × kernel height × kernel width × input channels of the filter), `DEPTHWISE_CONV_2D` (output elements × kernel height × kernel width) and `FULLY_CONNECTED` (output elements × input features), every kernel position included also under `same` padding. Not counted: bias additions, element-wise arithmetic (`ADD`, `MUL`), pooling and `MEAN`, activations, `SOFTMAX`, (de)quantization and data movement; those operators are listed with the number of elements they produce. An operator the script knows neither as counted nor as free of MACs is named in the table and ends the run with exit code 3 instead of being counted as zero. The graph is read from the flatbuffer with the schema TensorFlow ships, not through the interpreter, so nothing is executed and no delegate is involved.

## 8. Shared Helpers
*   **`artifacts.py`**: Not run directly. Holds the three rules the training, quantization and evaluation scripts share: the run name (`{model}[_{tag}]+{batch}+{epochs}+{lr}+{W}+{H}`), the refusal to replace an existing output without `--overwrite`, and the label order that travels with each model (`.classes.txt`). It also writes the training record. Standard library only.
*   **`cli.py`**: Not run directly. Provides the argument parser every script uses, which accepts each multi-word option with `_` or `-`.
*   **`images.py`**: Not run directly. The one place where an image file becomes the array a model receives: Pillow opens it, converts it to grayscale (`convert('L')`) or RGB, resizes it with LANCZOS only when its size is not the model's, and returns raw `uint8` pixels. Training, the calibration of the quantizer, MIL, SIL and the PIL bench all read through it, in a fixed order (classes, then file names), so the same file gives the same bytes at every level; the HIL bench works on the frames the camera captures and does not use it. Needs only Pillow and numpy.
*   **`evaluation.py`**: Not run directly. What the two PC levels do once they have the output of a model, so that `mil_benchmark.py` and `sil_benchmark.py` cannot drift apart: the label order that travels with the model and its check against the folders of the test split, the predicted label of every image, accuracy, weighted precision, recall and F1, macro-F1 and the per-class report, the confusion matrix and its plot, and the three result files (`confusion_matrix_`, `predictions_` and `metrics_{model}`). Each script keeps what is its own: how the model is loaded and run, its options, and the keys it adds to the `model` and `dataset` blocks. It imports scikit-learn, seaborn and matplotlib, not TensorFlow.
*   **`train_common.py`**: Not run directly. What the three training scripts share: the `train` and `val` partitions loaded into memory through `images.py`, the recipe options (`--lr_schedule`, `--augmentation`) and the recipe fields of the training record.
*   **`boards.py`**: Not run directly. Lists what changes with the board (core, FQBN, camera, default results folder, the name the firmware announces) and holds the text the two board benches wait for at the end of an inference, the reading of the identity lines of the firmware (`BOARD:`, `INPUT_SHAPE:`, `MODEL_BYTES:`, `MODEL_FNV1A:`, `ARENA_USED:`) and the FNV-1a fingerprint of a model file. `compile_upload_arduino.py`, `pil_benchmark.py` and `hil_benchmark.py` take their `--board` choices from it.

## Usage Notes

- **Software behind a result:** `mil_benchmark.py`, `sil_benchmark.py`, `pil_benchmark.py` and `hil_benchmark.py` write to their `metrics_{model}.json` a `software` block with the versions that can change a figure: Python, the operating system and the packages the level uses (TensorFlow and Keras where a model runs on the PC, numpy, scikit-learn, Pillow where image files are decoded, pyserial and OpenCV on the board benches), with the key names of the training record. One helper writes it for the four, `artifacts.software_versions()`; it imports nothing, so the PIL bench still runs without TensorFlow.
- **Options shared by the four levels:** `mil_benchmark.py`, `sil_benchmark.py`, `pil_benchmark.py` and `hil_benchmark.py` all take `--model_path` (the model the level evaluates), `--splits_dir` (the partition, default `data/splits`), `--output_dir` (default `results/{mil,sil,pil,hil}`) and `--overwrite`. Every level writes `confusion_matrix_{model}.png` and `metrics_{model}.json`, plus `predictions_{model}.csv` (MIL, SIL, PIL), `latency_metrics_{model}.csv` (PIL, HIL) and `conditions_{model}.json` (HIL). The two board benches also share `--port`, `--board`, `--baud`, `--count`, `--delay`, `--gap`, `--folder` and `--allow_model_mismatch`, and both stop before measuring when the fingerprint the firmware reports is not that of `--model_path`. `--board` (default `portenta`) is checked against the board the firmware announces, and with `--board nicla` the default output folder is `results/nicla/{pil,hil}`.
- **Option spelling:** Every multi-word option can be written with `_` or `-` (`--output_dir` or `--output-dir`). This document and `--help` use `_`.
- **`--help` without TensorFlow:** The scripts that use TensorFlow (`mil_benchmark.py`, `sil_benchmark.py`, `quantize_int8_basic.py` and the three training scripts) read their command line before they import it, so `--help` and a wrong option answer in a fraction of a second instead of after TensorFlow has loaded, and asking a training script for its help creates no folder.
- **One image loader:** MIL, SIL and the PIL bench read every image through `images.py`. The results published before it existed (the vehicle benchmark and the Visual Wake Words run) were measured with TensorFlow decoding the JPEG files at MIL and SIL and Pillow at PIL, and the two decoders do not give the same pixels. Re-running those models through the loader changes the prediction of 0 to 7 of the 940 test images at MIL and of 4 to 33 at SIL (5 and 14 of 300 on Visual Wake Words), so a re-run of a published MIL or SIL result differs from the published file by that much. `RelPath` in `predictions_*.csv` is written with `/` on every operating system (the published files of the vehicle benchmark, made on Windows, have `\`).
- **PNG partition:** The images of the full COCO partition are stored as lossless PNG (`reshape_images.py --format png`: 160×120, one channel), and the loader reads `.png` and `.jpg` alike. A JPEG file does not fix its pixels, the decoder does: on 200 JPEG files of the earlier 12,000-image COCO partition TensorFlow 2.21.0 and the loader (Pillow) disagree on every one, by up to 24 grey levels, while OpenCV 4.13.0 agrees with the loader. On 200 files of the PNG partition the three give identical pixels, so what a level reads no longer depends on the library or its version. The vehicle and Visual Wake Words partitions stay JPEG, as they were measured.

- **Data preparation:** `--balance undersample` trims every class to the size of the smallest; leave it out to keep the natural class ratio. Run it once with `--dry_run` to see how many images each class would lose — on the vehicle benchmark it goes from 7,525 images (4,387 / 3,138) to 6,276 (3,138 / 3,138).
- **Partition:** `split_dataset.py` also flags the `hil_subset` of the test split that the HIL step uses — 200 images, half per class.
- **Training:** All three training scripts accept `--splits_dir` (default `data/splits`) to point at a different partition, and write TensorBoard logs to `tensorboard_logs/`. The recipe options (`--lr_schedule`, `--augmentation`, `--trainable_backbone`) are described under [Model Training](#2-model-training-ml-pipelines).
- **Published partitions:** To run a level on a published partition, point it there with `--splits_dir data/splits_coco`, `--splits_dir data/splits_plates` or `--splits_dir data/splits_vww`. The result files of the published models already exist, so write elsewhere with `--output_dir` (for example `results/smoke_test/mil`, which is git-ignored) and check the run with `compare_results.py`, or add `--overwrite`.
- **Exit codes:** Every script ends with a non-zero exit code when it reports an error (a missing model or partition, no image found, a failed conversion or training), so a chained pipeline stops at the failed step.
- **MIL evaluation:** `--model_path` is required — there is no default checkpoint. `--data_dir` defaults to `<splits_dir>/test`, and `--splits_dir` to `data/splits`. The Confusion Matrix, `metrics_{model}.json` and `predictions_{model}.csv` are written to `results/mil/`.
- **INT8 quantization:** `--calib_seed` fixes the shuffle of the calibration images, so the same checkpoint always yields a bit-identical `.tflite`. `--splits_dir` defaults to `data/splits`.
- **SIL evaluation:** Reads `data/splits/test` by default; override the partition root with `--splits_dir` or a single directory with `--data_dir`. The input geometry is taken from the model's own input tensor, so `--width`/`--height` are corrected automatically if they disagree. Outputs go to `results/sil/`, with the same three artifacts as MIL. Always pass `--model_path` explicitly.
- **Header generation:** Use `--target pil` or `--target hil` to generate only one of them. Arduino sketches are self-contained folders, so each one needs its own copy of `model.h`. The generated symbol is `g_model`, which is what both `.ino` sketches reference in `tflite::GetModel()` — override it with `--var_name` only if you also change the firmware.
- **Compile and upload:** The board runs one firmware at a time, so `--target` has no "both" option. Use `--target hil` for the camera-in-the-loop firmware of the HIL step. The board's port is auto-detected via `arduino-cli board list`, so no port argument is needed; `--sketch_path` accepts an arbitrary sketch folder. Alternatively, you can open the project folder in the Arduino IDE and click Upload.
- **PIL evaluation:** This is Processor-in-the-Loop: the real chip runs inference, but the image is injected over the wire — the camera and physical scene are not part of the loop. `--model_path` is not loaded on the host: it names the run's artifacts after the model flashed on the board, the same convention `mil_benchmark.py` uses, so benchmarking a second model no longer overwrites the first one's results. Override the partition root with `--splits_dir`, or send an arbitrary folder with `--folder`; `--count N` sends a random subset. Note `--width`/`--height` default to 320×320, so pass them explicitly for a 160×120 model. The Confusion Matrix, `latency_metrics_{model}_int8.csv`, `metrics_{model}_int8.json` and `predictions_{model}_int8.csv` are written to `results/pil/`, or to `--output_dir`. The bench stops before opening the port if those files already exist, unless `--overwrite` is given.
- **HIL evaluation:** This is the Hardware-in-the-Loop level: ground truth is known by construction from the displayed stimulus, and `--sil_model`/`--mil_model` enable cross-running the exact captured frame through the lower fidelity levels to decompose the gap. Stimuli default to the `hil_subset` of `<splits_dir>/test_manifest.csv` (`--splits_dir`, default `data/splits`; `--manifest` points at a specific file); use `--all_test` for the whole test split. The bench aborts if the firmware's model fingerprint does not match the `.tflite` — `--model_path` sets it explicitly (`--tflite` is the same option), otherwise `--sil_model` is used — or if any of `--lux`, `--distance_cm`, `--ambient_temp` is missing. It also stops, before opening the port, if its output files already exist, unless `--overwrite` is given. A session that ends before its last stimulus keeps its rows and writes its files marked `completed: false`, with exit code 3. `confusion_matrix_{model}_int8.png`, `metrics_{model}_int8.json`, `latency_metrics_{model}_int8.csv` and `conditions_{model}_int8.json` are written to `results/hil/`, plus `data/hil_frames/` when `--dump_frames` is passed.
- **Repeated HIL sessions:** Give each session its own folder and tag:
  ```bash
  python src/hil_benchmark.py --port COM9 --model_path models/tflite/{model_name}_int8.tflite --lux 10 --distance_cm 24 --ambient_temp 24 --output_dir results/hil/rep1 --model_tag {model_name}_rep1 --notes "replica 1"
  ```
