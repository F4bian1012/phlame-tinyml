Flash budget of the two firmwares on the Arduino Portenta H7: build record
==========================================================================

This file backs the "Flash Budget" figures of docs/hardware.md, which README.md quotes under "Known
Limitations". It records two real builds, one of each sketch, made on 2026-11-15 from the sources of
the commit that updates this file, with the model header of the repository:
deployment/pil_firmware/model.h and deployment/hil_firmware/model.h, which both carry the published
MobileNetV2 of the COCO benchmark (644,648 bytes; FNV-1a fingerprint ad34723a; SHA-256
dc09c7c071de5180525e0e6cd7929410b1a34cd200362759849df81a4063d9a9, the entry
models/tflite/MobileNetV2_COCO+32+50+0.0003+160+120_int8.tflite of models/checksums.sha256). That
commit changes documents only: the sketches and the headers built are those of commit eb83a0e.

Nothing was uploaded: the builds were made with --compile_only, which does not look for a board.
Paths are given relative to the repository; "<build>" is the folder given with --build_path.


Toolchain
---------
  arduino-cli              1.5.0
  core                     arduino:mbed_portenta 4.5.0
  FQBN                     arduino:mbed_portenta:envie_m7:split=100_0
  compiler                 arm-none-eabi-gcc 7-2017q4 (installed with the core)
  library                  Chirale_TensorFlowLite 2.0.0, with AllOpsResolver (every kernel is linked)
  host                     Windows 11


Commands (from the repository root)
-----------------------------------
  python src/compile_upload_arduino.py --target pil --compile_only --build_path <build>
  python src/compile_upload_arduino.py --target hil --compile_only --build_path <build>

Each build had a folder of its own, with a short path outside the repository: on Windows the build
fails when a path inside that folder passes 260 characters.


Output of the script (PIL build; the HIL build prints the same with hil_firmware)
---------------------------------------------------------------------------------

  Core arduino:mbed_portenta is already installed.

  === 1. Compiling project at: deployment\pil_firmware (Portenta H7) ===
  > arduino-cli compile --fqbn arduino:mbed_portenta:envie_m7:split=100_0 --warnings none --build-path "<build>" "deployment\pil_firmware"
   Compilation successful.

For this board arduino-cli printed no size summary (on this PC it prints it in Spanish, "El Sketch
usa ... bytes", for the Nicla Vision), so the sizes below were read from the files of the build
folder: the size of each image, the sections of the .elf as listed by
"arm-none-eabi-size -A <build>/<sketch>.ino.elf", and the linker script of the build.

Linker script of the build (<build>/linker_script.ld)
------------------------------------------------------
  FLASH (rx) : ORIGIN = 0x8040000, LENGTH = 0x60000000 - 0x8040000

The application starts 0x40000 bytes (256 KiB) into the internal flash (0x08000000 to 0x081FFFFF,
2 MiB): the first 256 KiB are the bootloader region. The length this script gives to FLASH is not
the size of the internal flash, so the linker does not refuse an image that is too big for it.


Budget derived from those figures (1 KiB = 1,024 bytes)

  bootloader region                               256.0 KiB       256.0 KiB
  firmware without the model                      417.7 KiB       431.7 KiB
      (application minus the 644,648 bytes of the model: 427,720 and 442,088 bytes)
  left for the model                            1,374.3 KiB     1,360.3 KiB
  image with this MobileNetV2 (629.5 KiB),
      bootloader region included                1,303.2 KiB     1,317.3 KiB
                                                  (1.27 MiB)      (1.29 MiB)

Only this MobileNetV2 was built for this record. The "flash used" figures of the other models in
docs/hardware.md are this budget plus the size of their .tflite, not separate builds.


Against the record before this one
----------------------------------
Until 15 November 2026 the two headers carried the MobileNetV2 of the vehicle application case
(645,640 bytes), and the record before this one, in the history of this file, was built with it.
That model is 992 bytes larger. Without the model the HIL firmware is the same 442,088 bytes, its
sketch not having changed in between; the PIL firmware is 16 bytes larger (427,720 against 427,704),
its sketch having gained the ARENA_MEMORY identity line in between.
